# 精度基准

这里只有一个数字口径：**我们自己合成的确定性片段**。它不是对 Klangio、Songscription、AnthemScore 或 Basic Pitch 的同口径对比，也不该被读成那种对比。真实的对手分数来自各自的私有测试集，我们既拿不到它们的音表，也没有 MIDI 渲染器（本机只有 `ffmpeg`，没有 fluidsynth/timidity 和 soundfont），所以无法在同一 ground truth 上给它们打分。任何人复现下面的数字都不需要下载音频。

## 口径

`scripts/bench_synth.py` 用固定种子生成一段钢琴音频，生成器自己持有音表，那就是 ground truth：

```bash
PYTHONPATH=src .venv/bin/python scripts/bench_synth.py --seed 1 --out bench/clip1.wav
```

- 21.0 秒，`bpm=96`，4/4，A 小调音阶
- 117 个音：右手 54（每八分音符一个，12% 休止）、左手 63（每小节第 1、3 拍块状和弦）
- 右手锁在 MIDI `[60,79]`，左手在 `45±`，都落在三档的骨架音域内
- 音表写在同目录的 `clip1.truth.json`

打分：

```bash
PYTHONPATH=src .venv/bin/python scripts/note_f1.py bench/clip1.truth.json out/clip1-easy.arr.pkl --tolerance 0.30
PYTHONPATH=src .venv/bin/python scripts/note_f1.py bench/clip1.truth.json out/clip1-easy.arr.pkl --tolerance 0.30 --role rh
```

一个预测音命中，当且仅当：音高**完全相同**、onset 相距 ≤ 0.30 秒、贪心一对一。0.30 秒不是宽松：分离加转写本身的 onset 抖动就在这个量级，压到 0.05 秒测的已经不是排谱而是强迫对齐。音级（pitch class）版本同样跑一份，音高差一个八度时它不会扣分——八度错误是我们已知的短板（见下），所以两个数都要看，不能只报高的那个。

预测音的音高要先减掉 `arr.meta['transpose']`，因为成品是移调到档位调号之后的结果，而真值在源调。

## 当前数字

`--tolerance 0.30`，`easy` 档，21 秒分离口径（`out/bench28`，`black_key_notes` 修复后重测）：

| 指标 | 数值 |
| --- | --- |
| note-F1（全体） | **0.5882**（precision 0.6897 / recall 0.5128，命中 60/117，预测 87） |
| pitch-class F1 | **0.6863**（precision 0.8046 / recall 0.5983，命中 70/117） |
| note-F1（右手） | 0.6667（precision 0.7083 / recall 0.6296） |
| note-F1（左手） | 0.5098（precision 0.6667 / recall 0.4127） |

召回是瓶颈，precision 已经不低：117 个真音符里只找回 60 个（`0.5128`），但预测出的 87 个里有 60 个对得上（`0.6897`）。左手 recall `0.4127` 是全表最弱的一列，`note-F1（左手）` 的下降主要来自漏音而不是错音。

另有一个独立样本 `bench/clip2.wav`（12 小节 4/4、72 bpm、41 秒、180 音符，`--seed 7 --bars 12 --bpm 72` 可重生成），同样 `--tolerance 0.30`、`easy` 档、`--no-separate` 口径：note-F1 **0.4309**（命中 78/180，预测 182）、pc-F1 **0.5470**。它比 clip1 低是口径不同（混合音频直接转写，没有分离），不是退化——两个样本之间不可横比，只用于验证节拍与尾小节。

三档 `easy`/`medium`/`hard` 的数字**完全相同**。这是设计，不是巧合：三档只差移调量（`global.black_key_rank` 决定），音高集合和节奏不变。任何一档的数字和其它档对不上，就是档位同构被破坏。

档位按**手上真正按到的黑键数**排序，不按调号。调号只是代理指标，而且实测是反的：曲子围绕非 C 的调写成时，写成 C 调会把它的每个变化音都变成黑键。修复前后（走生产默认路径，即分离后的伴奏；20 个产物全量跑 `--preset all --seconds 21`，`clip2` 用 `--seconds 41`）：

| 样本 | 档 | 修复前 调号 / 黑键音 | 修复后 调号 / 黑键音 |
| --- | --- | --- | --- |
| `clip1` | easy | Am / **27** | G / **2** |
| `clip1` | medium | Cm / 3 | C / 3 |
| `clip1` | hard | Fm / 9 | D / 6 |
| `clip2` | easy | Am / **70** | C / **4** |
| `clip2` | medium | Cm / 16 | G / 18 |
| `clip2` | hard | Fm / 24 | F / 26 |

三档同构性用 `sorted((round(start,4), pitch - meta["transpose"]))` 逐手比对，六个 arm 全部相等。

同构靠的是「在源调构建、最后一次移调」：`pcs = scale_pcs(source_key)` 在前，`shift` 在最后，所以三档吸附用的是同一套音级，档位只能平移，不能增删音符。副作用是**音符不一定都落在印刷的调号内**——`clip1` 三档各有 3 个音留在印刷调外，它们其实是源调的同一对音级 `D♯` 和 `F♮`（G 大调的 `♯4` 与 `♭7`），只是跟着移调换了拼法：easy 印作 `D♯`/`F`，medium 印作 `G♯`/`A♯`，hard 印作 `A♯`/`C`。以 easy 为基准正好差 `+5` 与 `-5` 个半音（medium = easy +5、hard = easy −5），位置逐位一致。这是故意的：让吸附跟着印刷调走，等于让调号泄进编配，档位就会真的不一样了。`clip2` 三档同样是 3 个（音级 `{6,8}` / `{1,3}` / `{1,11}`），位置同样逐位一致。

## `--no-separate` 曾经偷读分离缓存

`--no-separate` 的语义是「不跑 demucs，直接转写混音」。但 `get_stems` 先查缓存、后看这个开关：只要 `cache/clip1-htdemucs-<seconds>s.npz` 存在，就把当年那次分离出来的伴奏喂给转写。于是同一段音频、同一个命令，结果取决于缓存里恰好躺着哪个 `--seconds` 的键：

| `--seconds` | 改前命中缓存 | 改前 源调 / 右手 / 左手 | 改后 源调 / 右手 / 左手 |
| --- | --- | --- | --- |
| 21 | 是（`clip1-htdemucs-21s.npz`） | **G** / 48 / 39 | C / 47 / 57 |
| 22 | 否 | C / 47 / 57 | C / 47 / 57 |

`bench/clip1.wav` 正好 21.0 秒，所以 `--seconds 21` 和 `--seconds 22` 截出来是同一段数组；改前两行差一个调、差 18 个左手音，差别只来自缓存。真值是 A 小调（相对大调 `C`），改前那个 `G` 是错的。生产默认路径照旧读缓存（日志仍是 `using cached stems cache/clip1-htdemucs-21s.npz`），不受影响。

`report.json` 现在把两个量分开报：`key_signature_accidentals` 是**调号**里落在黑键上的音级数（`G` 大调 → `F#`，所以是 1），`black_key_notes` 是**音符**里落在黑键上的个数（`clip1` 三档 `2 / 3 / 6`，与直接数 pickle 逐位相同）。旧字段名 `accidental_pitch_classes` 一个名字兼指两者，档位顺序就是被它带反的，现在保留只为兼容，新代码请读 `black_key_notes`。

## 小节宽度验收（用户反馈「多一拍 / 少半拍」）

用户说的问题是**某一小节多一拍或少半拍**，所以判据是每小节的总时值，不是小节数——只数小节线会漏掉「小节数对、但里面装错了拍」这种情况。`scripts/bar_audit.py` 把每个小节格子里的符值加起来（简谱认 `[a+b]` 取最长成员、`(...)` 左右手取较长者），和拍号比对：

| 样本 | 简谱 修复前 | 简谱 修复后 | 五线谱 修复前 → 修复后 |
| --- | --- | --- | --- |
| `clip1` 8 小节 4/4 @96 | 4/8 小节正好 4 拍，`off: [3.75, 3.5, 3.5, 3.5]` | **8/8，`off: []`** | 16/16 → 16/16 |
| `clip2` 12 小节 4/4 @72 | 11/12 小节正好 4 拍，`off: [3.75]` | **12/12，`off: []`** | 24/24 → 24/24 |

三档全部命中，一共 13 个 stem×tier arm，零个偏离拍号的小节。五线谱本来就准，是因为 MusicXML 的时值由渲染器自己按小节切开；错的是简谱那一侧，而用户看到的正是简谱。

修了四处，都是叠加的，不能只报一处：

1. **格子里的符值不合计拍号**。一拍之内晚出场的符保留了未截断的时值，小节于是变成 4.25 拍；跨小节线的延音被当成「晚开始」，于是补了一个不该有的前导休止；延音长度按音符自身长度算，而不是按它的**结束位置**算。现在格子严格等于 `beats_per_bar`。
2. **pickle 里带着最后一个小节线之后的音**。两个渲染器本来就会裁掉它们，所以玩家在任何界面上都看不到，但它们让音符计数对不上（`clip1` 92 vs 87、`clip2` 183 vs 182）。现在在源头裁掉，并把谱长固定在 `meta["score_beats"]`，避免「按裁过的音重新算长度 → 再裁一次」的自我引用。
3. **小节预算多给了一小节**（`int(duration / bar) + 1`）。单独改这一处渲染结果完全不变（`bench17` 与 `bench15` 数值逐位相同），它的价值只是让 pickle 不再带有谱外音。
4. 速度八度与网格：`clip1` 旧 47.85 bpm / 18 拍 → 新 96.60 bpm / 33 拍；`clip2` 旧 144.02 bpm / 96 拍 → 新 71.99 bpm / 48 拍。两个样本错法相反（一个半速、一个倍速），都由同一个重音判别器修正。

另有一个**独立**的读谱验收：`scripts/jianpu_roundtrip.py` 是一个真的简谱读取器，把印出来的谱子读回音高，和 pickle 逐音比对。六个 arm 全部 `identical`（`clip1` 87/87、`clip2` 182/182，`extra=[] missing=[]`）。两个容易读错的约定：文件的 `1=` 是 `arr.key_signature` 的**关系大调**（`Am` 印 `1=C`），平八度从中间 C 八度里的那个主音开始；长度点与八度点写在缀在数字与变化音之后（`#4'._`），所以要先剥 `_.` 再数 `'`/`,`。

### 第三轮：格子里的「洞」和整拍休止的右手

上表是 2026-11 之前的口径，它**看不见**下面这类错误，因为 `bar_audit.py` 把格子读成 `max(rh, lh)`：两只手里只要有一只写满了这一拍，小节就照样合计成 4 拍。用户听到的「少半拍」恰恰藏在其中：

```
旧：| ... | 6,__ 5,__ 0__([4,,+1,]) | ... |
新：| ... | 6,__ 0__ 5,__ 0__([4,,+1,]) | ... |
```

两个音实际落在 0.00 和 0.50 拍，印出来却成了相邻的两个十六分音符，中间那 0.25 拍的洞没有休止符，读谱的人只能把它们读成 0.00 和 0.25。另一处是右手整拍不动的时候，旧代码打印 `([1,,+2,,+6,,])`——一个只有左手的格子，右手在这一拍没有任何符号，格子读不成一整拍。

所以判据升级成三问，缺一条都不算修好：

| 判据 | 旧 | 新 |
| --- | --- | --- |
| 每小节合计拍号（`max(rh, lh)`） | 8/8、12/12 全过 | 8/8、12/12 全过 |
| **每只手单独合计**（`hand_short_cells`） | `clip1` 每档 6 个格子短，三档 18 个 | **0** |
| 每只手每小节合计（容差 1e-6） | `clip1` 每档 4 小节短，共 12 小节，缺 2.00 拍 | **0 小节短，缺 0.00 拍** |

A/B 用**同一批 pickle**（`/tmp/fix31b`、`/tmp/fixc2b`）分别喂旧、新 `notation.py`，所以差异只可能来自简谱文本层：

| 样本 | 修复前 | 修复后 |
| --- | --- | --- |
| `clip1` easy / medium / hard | 8 小节，4 小节短，合计缺 2.00 拍/档 | 8 小节，**0 小节短，缺 0.00 拍** |
| `clip2` easy / medium / hard | 12 小节，0 小节短 | 12 小节，0 小节短（**逐字节不变**） |

`clip2` 三档输出与修复前 `cmp` 完全一致——这不是巧合，是这次只动了 `clip1` 真有的两种情形，说明改动范围没有外溢。

同期还要确认这次没有靠「编音符」把宽度凑够，所以另外两个已有验收必须同时保持：

- `scripts/jianpu_roundtrip.py`：六个 arm 仍全部 `identical`（`clip1` 87/87、`clip2` 139/139），`extra=[] missing=[]`。休止符不产生音高，所以宽度是修出来的、不是填出来的。
- 同一批 pickle 的 `.musicxml` / `.mid` / `report.json` 的 `stats` **逐字节相同**。五线谱本来就对，这次改的只是简谱那一侧的拼写。
- 延音 `-` 抽查：`clip1` 每档 19 个、`clip2` 每档 26 个 `-`，逐个回查 pickle 里是否有音正在响，`unbacked=0`。

`beat_track` 还会把拍点排到文件末尾的静音里（`clip1` 最后一拍 RMS 0.0005、中位 0.1116），`_drop_tail_silence` 按本曲 RMS 中位的 5% 只裁尾部连续拍；在 60 秒真实录音上裁 0 个，即门限在真实素材上是惰性的。

## 已知短板

- **八度错误**。`cqt_melody` 的谐波累加方向反了：`sal[: n_bins - shift] += w * C[shift:]` 把高 bin 的能量加到低 bin，造成系统性低八度偏置。半音差直方图上 `-12` 出现 5 次。pc-F1 明显高于 note-F1 的一部分原因就在这里。
- **旧字段 `meta['accidental_pitch_classes']` 指的是调号不是音符**（等于 `key_signature_accidentals`），也不来自 `allowed_black_keys`（后者是吸附半径，不是上限）。判档位请读 `black_key_notes`，或直接数 `pitch % 12`。
- **速度八度已经修好，但不是靠对比度**。旧规则要求倍速网格的对比度好 4 倍，实测最好只有 2.3 倍，所以从未触发；现在改用重音（`clip1` 正确速度 1.32、半速 0.64）。
- **左手偏弱**。左手 note-F1 0.4952，低于右手 0.6538。左手是折叠出来的，真值里的块状和弦本来就不该被逐音还原，这个数字的含义要弱于右手。
- **没有 MIDI 渲染器**，所以无法在别人的测试集上算同口径分数。

改动任何一环，上面的表都要重跑；数字掉了就是掉了，不要换容差、不要换口径、不要只报 pc-F1。
